# Typed fields, typed arrays and strict type checking

Verification on 2026-11-22 used MiniLangCompilerPy and the rebuilt
MiniLangCompilerML from the same source revision of the feature.

## Correctness and byte parity

- The Python regression runner passed 263 tests. The self-hosted MiniLang
  harness passed 179 tests.
- Seven fixtures across Windows x64, Linux x64 and MinUX x64 produced
  63 byte-identical images within their target and fixture groups. The
  compiler paths were Python, self-hosted monolithic and self-hosted
  object pipeline. All seven Windows fixtures ran successfully.
- The field, typed array and packed array fixtures also ran under Linux
  (WSL) and MinUX (QEMU). The Windows concurrent-GC variants passed with
  byte parity across all three compiler paths.
- The Windows incremental regression matrix ran 180 byte-identical
  clean, cold-cache and warm-cache images within their fixture groups.
  Changing the body of an imported leaf function from an integer return
  to a string return invalidated the caller's strict type proof in all
  three compiler paths.
- The existing positional and named struct-default tests pass with the
  new field checks. The field fixture covers aliases, inherited fields,
  constructor failures, and a class member with an array contract.

The Python and self-hosted builds of the complete compiler matched on
each target. Windows and Linux used native self-hosting. MinUX used a
packed cross-build.

## Windows x64 microbenchmarks

Both compilers generated byte-identical executables for each variant.
Timing is wall time with process startup included. Each pair alternated
execution order, discarded three warm-up trials and measured 20 trials.
The executables used `--no-gc-periodic`.

### One million signed integers

[`packed_array_storage.ml`](../../benchmarks/packed_array_storage.ml) allocates
one million cells, writes and reads each one, and checks the same sum
(`499999500000`) in both variants. Pass `-D PACKED=true` for the compact
implementation. Heap bytes are the change in `heap_bytes_used()` after
allocating the collection.

| Variant | Heap bytes | Median | Range |
| --- | ---: | ---: | ---: |
| Ordinary array | 8,000,016 | 16.53 ms | 15.30–18.23 ms |
| `Int32Array` | 4,000,048 | 44.57 ms | 43.63–51.47 ms |

`Int32Array` roughly halves collection storage. Its checked method calls
cost more than optimized native indexing in this access-heavy workload.

### Twenty million typed array writes

[`typed_array_store.ml`](../../benchmarks/typed_array_store.ml) uses the same
`array<int>` in both variants. Pass `-D PROVEN=true` to annotate the local
binding. Both variants produce the checksum `14`.

| Binding | Element validation call sites | Median | Range |
| --- | ---: | ---: | ---: |
| Ordinary binding holding a typed array | 2 | 53.36 ms | 51.27–68.02 ms |
| Fixed `array<int>` binding | 1 | 55.89 ms | 54.14–60.63 ms |

One call site validates the initial copy in both binaries. The fixed binding
lets the compiler prove the literal store safe and remove the loop's element
check. That removal yielded no speedup in this benchmark. The executable
size was 85,504 bytes for both variants.
